# Текущее состояние проекта

## Назначение

Веб-приложение для учёта удостоверений сотрудников, кадровых назначений и договорных работ. Стек: React + TypeScript, Express, Prisma 7, MySQL.

## Разделы интерфейса

- **Сотрудники:** учёт удостоверений, карточки сотрудников, графики смен, радар-карты и IFO.
- **Работы и объекты:** базы, месторождения, скважины, координаторы, договоры и работы.
- **Справочники:** базы, сотрудники, должности, виды удостоверений, статусы, заказчики и виды работ. Изменения справочников выполняет администратор.
- **Общие разделы:** уведомления, сообщения и журнал аудита.
- **Настройки:** персональная цветовая тема и смена пароля через меню профиля.

## Организационные связи

Карточка `Employee` связана с учётной записью `User`. Текущее и исторические назначения хранят базу, должность, подразделение, руководителя и период действия. Администратор создаёт/редактирует пользователей через справочник сотрудников и задаёт назначение на странице «Сотрудники и назначения».

Месторождение создаётся в «Работы и объекты → Месторождения и скважины»: сначала нужна активная база из «Справочники → Базы». Там же добавляются скважины и назначается координатор месторождения. Один координатор может курировать несколько месторождений одной базы; назначение ограничено его активной системной ролью и базой.

Договор и допсоглашение создаются в «Работы и объекты → Договоры и работы». Договорное основание назначается скважинам вручную либо массово нескольким скважинам одного месторождения. Назначение сохраняет период действия. При записи фактической работы сервер проверяет единственное основание на дату, базу, статус договора и разрешённый вид работ.

## Роли и доступ

Сервер проверяет роли и базовую область доступа для каждой операции. Администратор управляет справочниками и всеми базами; менеджер работает в пределах своей базы; координатор видит закреплённые месторождения и команду; старший механик — глобальная роль компании. Не назначенные после переноса данные могут иметь подразделение `UNASSIGNED`; заполните назначения в карточках сотрудников.

## Локальный запуск

```powershell
npm install
npm run db:up
npm run migrate:deploy -w @app/api
npm run db:seed
npm run dev
```

Откройте `http://localhost:4100`. Данные администратора задаются `SEED_ADMIN_LOGIN` и `SEED_ADMIN_PASSWORD` в `app/api/.env`. Демо-данные загружаются отдельной командой `npm run db:demo`; используйте только для локальной/тестовой базы.

## Изменения схемы БД

1. Измените `app/api/prisma/schema.prisma`.
2. Создайте миграцию Prisma с SQL-файлом в новой папке `app/api/prisma/migrations/<timestamp>_<name>/migration.sql`.
3. Проверьте миграцию на локальной копии БД.
4. Примените `npm run migrate:deploy -w @app/api`. Не используйте reset на базе с нужными данными.

## Основные команды

```powershell
npm run typecheck

```

Интеграционные тесты API требуют MySQL и тестовую конфигурацию `app/api/.env.test`.

## Известные ограничения текущей реализации

- Расписание включает годовую таблицу и календарное редактирование; события, отсутствия, согласования, интеграционные и массовые операции пока не реализованы как полноценные модули.
- Разделы оборудования и часть графиковых экранов являются заготовками.
- Для массовой привязки договора к нескольким скважинам UI выполняет отдельный запрос на каждую скважину. При сбое посередине часть привязок уже может быть сохранена.
- Текущие организационные данные нужно сверить и заполнить; импортированные назначения могут остаться `UNASSIGNED`.

## Структура кода и комментарии

- `app/web/src/modules` — страницы пользовательских разделов.
- `app/api/src/modules` — маршруты, контроллеры и бизнес-логика API.
- `app/api/prisma` — схема данных, миграции и seed-скрипты.
- `shared/core` и `shared/ui` — типы, схемы проверки, общая логика и визуальные компоненты.

Комментарии к экспортируемым функциям добавляются возле публичных API и функций со сложными бизнес-правилами. В комментарии следует указать назначение, значимые входы и результат; тривиальный JSX/геттеры комментировать не нужно.

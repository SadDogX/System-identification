# Учёт удостоверений сотрудников

Веб-приложение для учёта удостоверений сотрудников и контроля сроков их действия.

**Стек:** React + TypeScript · Node.js + Express · Prisma · MySQL · JWT.

## Зависимости — только необходимое

| Где | Пакеты |
|---|---|
| Сервер | `express`, `@prisma/client` (+ `prisma` CLI для миграций) |
| Клиент | `react`, `react-dom` (+ `esbuild` для сборки) |
| Общее | `typescript` — только проверка типов; типы `@types/*` |

Всё остальное — встроенные возможности Node.js или несколько строк своего кода:

- TypeScript запускает сам Node (type stripping) — без tsx/ts-node, поэтому в импортах указаны расширения `.ts`;
- тесты — `node:test` и `fetch`, перезапуск при изменениях — `node --watch`, переменные окружения — `--env-file`;
- пароли — scrypt из `node:crypto`, JWT (HS256) — `server/src/utils/jwt.ts`;
- валидация — `shared/src/validation.ts` (одна и та же схема на клиенте и сервере);
- интерфейс — свой CSS (`client/src/styles.css`), SVG-иконки, мини-роутер (`client/src/router.tsx`) и загрузка данных (`client/src/data.ts`);
- клиент раздаёт тот же Express-сервер: один адрес, без CORS и прокси.

## Структура

```
client/   интерфейс (React)
server/   API (Express + Prisma), ежедневная проверка сроков
shared/   общий код: расчёт статуса и дат, схемы валидации, типы
```

## Запуск для разработки

Нужны Node.js 22.18+ (или 23.6+) и Docker.

```bash
npm install
npm run db:up                      # MySQL 8 в Docker, порт 3308
cp server/.env.example server/.env # если .env ещё нет
npm run db:migrate                 # создать таблицы
npm run db:seed                    # первый администратор + справочник
npm run dev                        # http://localhost:4100 — сервер и интерфейс
```

В режиме `dev` клиент пересобирается при изменениях (страницу в браузере нужно обновить), сервер перезапускается сам.
Продакшен: `npm start` — сборка клиента и запуск сервера.

Первый вход: логин и пароль из `SEED_ADMIN_LOGIN` / `SEED_ADMIN_PASSWORD` в `server/.env`
(по умолчанию `admin` / `admin12345`). При первом входе система попросит сменить пароль.

## Почта

Сотрудник с указанным email получает письмо, когда у его удостоверения срок становится жёлтым или красным
(пороги 90 / 30 / 10 / 0 дней, без повторов). Администраторы с email — раз в день сводку по всем красным и жёлтым.
Отправка идёт через свой SMTP-клиент (`server/src/utils/smtp.ts`): TLS или STARTTLS, вход по логину и паролю.

Настройки — переменные `SMTP_*` и `APP_URL` в `server/.env`. Если `SMTP_HOST` пустой, письма не отправляются.

Для локальной проверки есть Mailpit: он принимает письма и показывает их в браузере.

```bash
docker compose up -d mailpit   # письма видны на http://localhost:8026
```

## Фото удостоверений

JPG, PNG, WebP или PDF до 5 МБ. Тип проверяется по содержимому файла. Файлы лежат в `server/uploads/credentials/`
(эту папку нужно включить в резервное копирование), а отдаются только владельцу и администраторам.


## Основные правила

| Правило | Где реализовано |
|---|---|
| Статус по дате окончания: > 90 дн. — зелёный, 11–90 — жёлтый, ≤ 10 и истёкшие — красный, нет даты — белый. Пороги хранятся в таблице `Setting` | `shared/src/status.ts` |
| Дни считаются по московскому времени | `shared/src/dates.ts` |
| Сотрудник вводит только дату выдачи; дата окончания = выдача + срок из справочника, считается на сервере | `server/src/services/credentials.service.ts` |
| Изменение срока в справочнике не пересчитывает уже введённые даты | `server/src/services/catalog.service.ts` |
| Новая позиция справочника сразу появляется у всех сотрудников; у администраторов удостоверений нет | `ensureUserCredentials`, `backfillCatalogItem` |
| Пометка на удаление: запись скрыта из списков и статистики, восстанавливается | `adminMark` / `adminUnmark` |
| Пользователи удаляются мягко (`isDeleted`), логин остаётся занятым | `users.service.ts` |
| Права проверяются на сервере; `userId` для `/api/me/*` берётся только из токена | `server/src/middleware/auth.ts`, `server/src/routes/me.routes.ts` |
| Блокировка, смена роли или пароля сразу отзывают токены (`tokenVersion`) | `auth.ts`, `users.service.ts` |
| Все изменения пишутся в журнал с «было/стало» | `server/src/services/audit.service.ts` |
| Уведомления о сроках: ежедневно в 08:00 МСК и при старте сервера, пороги 90/30/10/0 дней, без дублей; администраторам — одна сводка в день | `server/src/jobs/expiryCheck.job.ts`, `notifications.service.ts` |
